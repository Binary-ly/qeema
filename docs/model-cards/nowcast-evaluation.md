Empirical coverage is the number that decides whether the interval
can be trusted. An interval claiming 80% and delivering 55% invites
exactly the false confidence this platform exists to avoid.

published as the nominal coverage above — deliberately wider than

## Caveat

A model evaluated on data generated by known rules will do better than one facing real markets, so read these as an upper bound. The interval-coverage figure is the more transferable of the two: a model that cannot calibrate its own uncertainty on easy data will not manage it on hard data.

## How the interval came to over-cover

This model previously published an 80% band that held **74.6%** of true values —
narrower than it claimed, so roughly one value in twenty fell outside a band
advertised to contain four in five. Not catastrophic, and the wrong direction to
be wrong in: a reader who trusts an 80% band is entitled to have it hold at
least that often.

Two remedies were documented. Both were measured on the same backtest rather
than argued about:

| Quantiles drawn | Conformal correction | Empirical coverage | Mean width | MAPE |
|---|---|---|---|---|
| 0.1 / 0.9 | none *(the original)* | 74.6% | 10.9% | 3.49% |
| 0.1 / 0.9 | split, random calibration set | 74.8% | 10.9% | 3.54% |
| 0.1 / 0.9 | split, most-recent calibration set | 77.1% | 11.8% | 3.76% |
| **0.05 / 0.95** | **none** *(shipped)* | **85.6%** | **14.3%** | **3.49%** |
| 0.05 / 0.95 | split, most-recent calibration set | 88.8% | 15.5% | 3.76% |
| 0.025 / 0.975 | none | 92.4% | 17.1% | 3.49% |

**Conformalised quantile regression was implemented, measured, and removed.**
It was the a-priori favourite: its coverage guarantee is distribution-free,
which is the property that should matter most for a model destined to meet real
markets unlike its training data. On this data it bought **+0.2 points** of
coverage — 74.6% to 74.8% — for a 25% reduction in training data.

The reason is instructive and is not a defect in the method. Split conformal
guarantees coverage under *exchangeability*, and a temporal backtest breaks
exchangeability by construction: the calibration rows are drawn from the
training period, while the test rows are weeks later, with prices that have
drifted under inflation and FX pass-through. Calibrating on the most recent
slice of training data instead of a random one recovered part of the gap —
74.8% to 77.1% — which confirms the diagnosis, and still did not reach the
claim.

So the shipped remedy is the simpler one: draw the band at 0.05/0.95 and publish
it as 80%. It reaches 85.6%, holds accuracy exactly (no data is held back), and
adds no machinery. `QUANTILES` and `NOMINAL_COVERAGE` are separate constants for
this reason, and a test asserts the first spans more than the second — the
margin is the point, and it would look like an inconsistency to anyone tidying
up.

**What this does not establish.** 85.6% is measured against synthetic data whose
price process the generator defined. The honest expectation on real markets is
lower, and the direction of the remaining error is unknown until there is real
data to measure against. The band is now wide enough to absorb some of that; how
much is not something this backtest can say.
